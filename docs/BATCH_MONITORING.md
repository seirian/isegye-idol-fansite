# 배치 모니터링 검토판

`feature/batch-monitoring`에서만 검토한다. 운영 main 병합, 기존 배치 일정 변경,
개별 배치 재실행, 복구 제어기 변경, 계정/시크릿/권한 변경을 포함하지 않는다.

## 제공 화면

- `/ops/batches/`: 기존 Google 로그인에서 **허용된 관리자**만 접근한다.
- 전체 8개 작업 요약, 실행/데이터 반영 분리, 예정/다음 시각, 실제 작업 시작,
  대기/소요 시간, 원본 실행 링크, 출처별 결과와 단계별 결과, 최대 30개 실행 이력.
- 멜론 TOP100/HOT100 등록 곡의 7일 관측표. 새벽 중지·부분·공백·미확인 구분.
- 실제 확인한 회차별 검증 결과만 90일 누적한다. 과거 미확인 구간은 생성하지 않는다.
- 45분 이상 오래되거나 조회에 실패한 스냅샷은 현재 정상으로 표시하지 않는다.
- 키보드 상세 패널, 상태 필터, 모바일 내부 표 스크롤, 색상 외 상태 문구 지원.

## 검토 단계의 갱신 범위 — 중요

실제 GitHub 실행과 체크섬 검증 산출물을 읽지만 **정기 스냅샷 갱신은 아직 연결하지 않았다.**
검토 브랜치 push 또는 허용된 수동 검토 워크플로 실행 때 새 스냅샷을 만든다.
브라우저 60초 새로고침은 저장된 자료를 다시 읽는 동작이며 새 배치를 실행하지 않는다.
사용자가 운영 구성을 승인하기 전에는 새 cron을 main에 설치하지 않는다.
새 기본 브랜치 워크플로가 없으므로 이 검토판이 자동으로 계속 최신이라고 표현하지 않는다.
이후 기존 일정과 분리된 GET-only 상태 수집기를 정기 실행하고 private 포인터만 갱신할 수 있다.

정식 반영 시에는 운영 인증 런타임 빌드에도 모니터링 확장을 연결해야 한다.
현재 검토 배포 뒤 별도 main 배포가 실행되면 기존 빌드가 검토 라우트를 제거할 수 있다.
실제 상태 수집 주기·보관 용량·알림 연계는 운영 반영 단계에서 확정한다.

## 안전 경계

GitHub 권한은 `contents: read`, `actions: read`뿐이다. 실행 API는 GET allow-list이며
POST/재실행/취소/issue 변경이나 원문 수집을 수행하지 않는다. 인증정보는 브라우저와 서버
스냅샷에 전달하지 않는다. 로그인/권한은 기존 Store/Session을 그대로 사용한다.
화면, CSS, JS, JSON 모두 동일한 서버 측 관리자 검사와 no-store를 적용한다.
원본 로그를 복사하지 않고 GitHub의 원본 실행으로 연결한다. 메시지는 textContent로만 출력한다.

기존의 KST due_slot과 evidence_ok를 읽기 전용으로 재사용한다. 성공 배지만으로 정상 처리하지 않는다.
공지 구버전 보고서는 명시적 readback이 없으면 현재 게시 검증으로 표시하지 않는다.
콘텐츠 목록은 전용 게시 증거가 없으므로 실행 성공이어도 데이터 반영은 `확인 불가`이다.
운영 배포는 auth-deployment.json의 deployed_and_verified, 현재 main 일치,
브라우저 검사와 비공개 경로 검사 증거를 대조한다. 실제 사용자 로그인 완료를 뜻하지 않는다.
완전 이력 조회는 워크플로당 100건 × 최대 20페이지, 전체 200 GET 이내이다.
조회 중 건수 변동, 중복 ID, 상한 초과는 최신 여부를 확정하지 않고 확인 불가로 처리한다.
아티팩트는 실행·attempt·커밋·해시·크기·JSON 멤버를 검증하고 실행하지 않는다.

## 배포와 복구

기존 공통 production 대기열/쓰기 잠금, 중지 변수, 고정 SFTP 서버 지문과 소유권 검사를 유지한다.
추가 쓰기 범위는 `.batch-monitoring/`, 검증된 immutable `.auth-runtime/`, 관리형 `access.php`이다.
운영 UI/피드/루트 .htaccess/다른 사이트 파일은 변경하지 않으며 전후 바이트를 대조한다.
기존 auth 파일이 예상과 다르면 변경을 강행하지 않는다. 활성 포인터와 entry를 백업하고
검증 실패 시 동시 변경 여부를 확인한 뒤 이전 값으로 되돌린다.
서버의 계정·설정·세션 파일은 배포 도구가 읽거나 쓰지 않는다.

새 데이터와 90일 요약 이력은 동일한 해시 manifest를 가진 immutable 릴리스로 발행한다.
이전 릴리스는 자동 삭제하지 않으므로 정식 상시 운영 전 보관 용량/승인된 정리 정책이 필요하다.
90일은 화면 데이터 범위이며 서버 물리 파일이 자동으로 90일 뒤 삭제된다는 뜻이 아니다.
실제 운영 스냅샷은 공개 소스나 검토 artifact에 포함하지 않는다.

## 검증

`python -m unittest discover -s tests -p test_batch_monitor.py -v`
`python scripts/build_batch_monitor_host.py`
`python tests/batch_monitor_host_browser.py`

단위 검사는 쓰기 API 차단, 현재 일정/새벽 중지/주간 경계, attempt 정렬,
불완전 조회, 증거 해시, 개인정보 필드 비복사, 이력 범위, 모든 리소스 권한,
POST/HEAD/손상/심볼릭링크를 포함한다. TLS 브라우저 검사는 기존 인증 회귀검사에
화면·필터·상세·모바일·오래된 자료·조회 실패·HTML 주입 방어를 추가한다.
브라우저 검사 계정과 스냅샷은 합성 테스트 자료이며 운영에 게시하지 않는다.
실제 배포 성공은 `batch-monitor-deployment.json`의 `gated_monitor_preview_verified`로 확인한다.
관리자 실제 계정으로 로그인하는 작업은 수행하지 않는다.
