# 관리자 수동 배치 실행

2026-11-17 사용자가 배치 목록 각각에 수동 실행 버튼을 요청했다. 기존 조회 전용
모니터링 수집기는 그대로 유지하고, 별도의 관리자 실행 요청 기능을 추가한다.
기존 문서의 "화면 전체 조회 전용" 설명은 본 기능에 한해 대체된다.

## 이용 흐름

8개 행의 수동 실행 버튼 → 영향 범위 안내·확인 체크 → 실행 요청 접수.
`운영 배포`는 전체 팬사이트 재배포이며 `배치 복구 점검`은 기존 복구 정책에 따라
다른 배치를 요청할 수 있으므로 별도 경고를 표시한다. 일괄 실행 버튼은 없다.

요청 접수와 실제 GitHub 실행을 구분한다. 요청 처리기는 5분 간격 예약 및 기존
배치/모니터링 종료 이벤트로 동작한다. GitHub 예약·대기열 지연 가능성이 있으므로
즉시 실행을 보장하지 않는다. 20분 안에 가져가지 않은 요청은 실행하지 않고 만료한다.
목록은 30초마다 수동 요청 상태를 확인하며 접수/조건 검사/실행/종료 및 원본 링크를
보여준다. 작업 종료 성공은 실제 데이터 반영 성공과 동일하지 않다.
예약·완료 이벤트의 이전 main SHA가 실행 전에 교체된 경우, 처리기는 진짜 같은
저장소 완료 이벤트인지 검증한 뒤 superseded로 성공 종료한다. 이 경우 요청 큐를
가져오지 않고 배치를 실행하지 않으며, 다음 정상 예약/이벤트가 요청을 처리한다.
현재 main 조회 자체가 실패하거나 SHA가 유효하지 않으면 기존대로 오류 종료한다.

대기 요청은 취소할 수 있다. 이미 시작된 GitHub 실행을 취소하는 기능은 제공하지
않는다. 네트워크 문제로 실행 여부가 불확실하면 자동으로 재전송하지 않는다.
관리자가 GitHub에서 확인한 뒤 미확인 요청을 해제해야 새 요청이 가능하다.

## 권한과 경계

`/ops/batches/control`, `manual.js`, `manual.css` 모두 기존 서버 세션의
role=admin AND allowed=true만 허용한다. POST는 기존 Session::requirePost의
CSRF·Origin·Fetch-Site 검사를 사용한다. 임의 workflow/ref/inputs를 받지 않으며
고정된 8개 배치, main 브랜치만 실행한다. 요청에는 128비트 식별자를 사용하고
같은 식별자의 재전송은 새 실행을 만들지 않는다.

웹서버·브라우저에 GitHub 토큰을 배포하지 않는다. 기존 SFTP 연결로 실행 처리기가
10분 유효한 임의 자격 증명의 해시만 비공개 control/agent.json에 배치한다.
`/ops/batches/_agent`는 이 자격으로 기존 승인 요청을 가져오고 결과만 기록한다.
계정·요청 생성 또는 모니터링 데이터 조회 권한은 없다. 처리 후 자격 파일을 제거한다.
실제 GitHub 토큰은 Actions 내부에서만 사용한다. 새 저장소 시크릿은 요구하지 않는다.

요청을 가져올 때와 실행 시도 직전에 기존 서버 Store로 요청자의 관리자 권한을
재검사한다. 이 검사는 정상 인증 런타임에서 이루어지며 SFTP 처리기는 계정/설정/
세션 파일을 내려받지 않는다. 익명 사용자에게는 실행 정보나 CSRF를 반환하지 않는다.

실행 전 GitHub에서 현재 main, 워크플로 활성 상태, 대기/실행 중인 모든 회차,
최근 수동·복구 요청을 재확인한다. 전역/개별 중지, 앨범 새벽 중지, 15분 대기 및
배치당 시간당 수동·복구 2회 상한을 적용한다. 새 ISEGYE_MANUAL_PAUSED=true는
수동 요청 실행만 중지한다. 확인 오류는 실행을 허용하지 않는다.
기존 배치의 자체 중지/공통 쓰기 잠금/검증/복구 규칙은 변경하지 않는다.

서버의 단일 잠금·원자적 JSON 교체로 요청 상태를 변경한다. GitHub POST 전에
되돌리지 않는 dispatching 기록을 남겨 작업 중단이나 불확실한 응답을 자동 재실행하지
않는다. API가 실제 실행 ID를 반환하고 그 실행의 저장소/경로/main이 검증돼야
원본 링크를 표시한다. 오래된 204 응답이나 통신 오류로 실행 ID가 없으면 미확인으로
남긴다. 외부 예약/기존 복구기와의 완전한 분산 원자성은 주장하지 않으며, 대상
워크플로의 기존 concurrency가 최종 직렬화를 유지한다.

요청 기록은 비공개 control 아래에 최대 256건. 완료 기록은 7일 또는 200건 초과 시
먼저 정리하며 진행/미확인 요청은 삭제하지 않는다. 사용자에게는 원본 계정 키를
보내지 않는다. 공개 Actions 산출물은 처리 건수·코드 검증 결과만 포함한다.

## 검증

Python `test_batch_manual.py`는 실제 네트워크/사용자 계정/배치를 사용하지 않는다.
격리 TLS `batch_manual_browser_checks.py`는 일반 회원·비로그인 차단, CSRF,
확인 전 미접수, 중복 방지, 취소, 권한 회수, 미확인 결과, 실행 링크, 다크모드와
모바일을 검사한다. 실제 운영 배포에서는 코드 바이트/익명 차단/처리기 준비 상태를
확인한다. 테스트를 위해 실제 관리자 세션이나 수동 요청을 만들지 않는다.
