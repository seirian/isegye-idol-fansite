# 음반 1차 검토 수정 — 2026-11-09

`feature/albums` 검토판만 갱신한다. main 병합, 운영 UI 및 운영 수집 배치 변경은 금지한다. 게시 성공 여부는 `review-albums-deployment.json`을 기준으로 판단한다.

## 요청 반영

- 목록 제목은 `한 곡에서 시작되는 이야기`로 복원한다.
- 음원 패널 제목은 `음원 연결`이다. 공식 플랫폼 사이트의 아이콘을 로고로 사용하고 로고 → 명칭 순으로 표시한다. 해당 링크의 뒤쪽 화살표 아이콘은 제거한다.
- 정보 범위 필터 및 해당 정렬 옵션을 제거한다. 이전 coverage URL 파라미터도 목록을 필터링하지 않는다.
- 멜론을 우선으로 국내 발매 앨범 표지를 확인하고, 확인 실패 시 지니·벅스 원본을 대조한다. 표지와 로고는 검증된 이미지 바이트를 검토 산출물에 넣어 외부 핫링크와 추적을 피한다. 미발매 영상에는 다른 앨범 표지를 붙이지 않는다.

## 자동 수집 추가

`refresh_album_review.py`가 기존 Apple·YouTube API 수집에 국내 카탈로그·차트와 선택적 Spotify 공식 API 수집을 결합한다. 멜론·지니·벅스 앨범 검색과 트랙 목록에서 아티스트·곡명·앨범을 대조하여 유일한 ID만 직접 연결한다. 멜론 좋아요는 페이지가 사용하는 공개 JSON 응답을 사용하며 HTML의 0 초기값은 사용하지 않는다.

멜론 TOP100/HOT100(100일), 지니 TOP200, 벅스 TOP100은 공개 차트 페이지에서 기준 시각과 순위 전체를 검증한다. 지니는 4개 페이지의 동일 시각과 1–200위 완전성을 확인한다. 이는 제휴 공식 API가 아니므로 화면에서 공개 페이지 수집이라고 구분한다. 로그인·CAPTCHA·접근 차단을 우회하지 않는다.

재수집 시 같은 음원·시각의 순위는 중복 저장하지 않고 30일 범위의 확인 기록을 이어간다. 한 번 수집한 순위는 한 점이며, 수집 이전 기록이나 중간 시각을 생성하지 않는다. 캐시는 영구 저장소가 아니며, 검토 단계에서 정기 스케줄은 아직 켜지 않는다.

## 수동 확인 항목

GitHub 저장소 접근 권한을 추가 요청할 필요는 없다. 음원 제공처 인증은 별도이다.

- Spotify: 해당 앱의 Client ID/Client Secret이 필요하다. 저장소 Actions secrets에 `ISEGYE_SPOTIFY_CLIENT_ID`, `ISEGYE_SPOTIFY_CLIENT_SECRET`으로 등록하면 다음 검토 수집 실행에서 Client Credentials 방식으로 자동 토큰 발급·메타데이터 연결한다. 키는 브라우저·HTML·로그에 출력하지 않는다. 로그인 사용자 정보는 요청하지 않는다. 공개 재생 횟수/과거 차트 이력이 제공된다고 주장하지 않는다.
- FLO: 공개 소스 계약을 별도 점검한다. 검증되지 않은 응답을 순위로 사용하지 않는다. 자동 연결되지 않은 경우 승인된 데이터 제공 경로나 제공처 인증 정보가 필요하다.
- 운영 전: 국내 표지·로고·공개 데이터의 재사용 및 정기 수집 조건을 확인한다. 기술적으로 읽을 수 있다는 것과 재배포 허락을 받은 것은 다르다. 검토판은 기존 관리자 전용 보호를 유지한다.

API 참고: https://developer.spotify.com/documentation/web-api/tutorials/client-credentials-flow
