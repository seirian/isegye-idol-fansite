# 카페 배치 운영 (2026-11-03)

정기 작업은 매시 17분 `schedule-refresh.yml`에서 세 출처를 함께 처리한다. 네이버 공식 검색 API에서 왁물원 단일 카페의 후보 신호 수만 확인한다. 검색 결과 자체는 저장·공개하지 않는다. 작성자/게시판/게시 시각을 검색만으로 검증할 수 없으므로 `searched`나 신호 0개는 '신규 글 0건' 또는 원본 전수 확인이 아니다. API 자격/접근이 없으면 `needs_setup`/`not_checked`가 표시된다. 같은 배치에서 `schedule/cafe-batches/*.json`의 검토된 자료를 중복 없이 발행한다. 마지막 원본 확인 시각은 매시간 덮어쓰지 않는다.

공개 원본 추가 검토는 Actions → **Cafe - collect approved public window** → Run workflow, main, KST 시작일을 지정한다. 최근 14일, 게시판당 최대 8페이지로 제한한다. 아카이브 전체를 되읽지 않고, 실패는 0건이 아닌 미확인으로 남긴다. 검증된 JSON은 실행 산출물과 `data/cafe-window-…` 브랜치에 남는다. 데이터 변경만 살펴본 뒤 병합하면 기존 운영 배포와 후속 피드가 반영한다. 예약 작업은 차단된 카페 페이지나 비공개 API를 반복 조회하지 않는다.

멤버/소속사는 기존 작성자·권한·게시판 검증, 뱅온정보는 지정 원문과 작성자·게시판·일자 형식이 일치하는 개별 공개 원문만 허용한다. 생방 상태, 휴방 확정, 임의 방송 시각으로 전환하지 않는다. 최초 아카이브·확인 시각과 증분 확인 시각을 구분한다. 삭제 시에는 해당 입력·허용 목록과 복구본 정리까지 동일하게 처리한다.
