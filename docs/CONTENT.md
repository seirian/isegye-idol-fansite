# 콘텐츠 운영

## 공개 자료의 범위

확인일: 2026-10-15. `src/data.js`의 SOURCES에는 공식 원문, 발표일(확인 가능한 경우), 확인일을 기록합니다. 공개 사실은 verified, 사이트의 이용·분류 안내는 editorial로 구분합니다. 공식 출처 배지는 사이트의 공식 승인 의미가 아닙니다.

## 추가 절차

1. 공개 가능한 공식 발표 또는 원본을 읽고 사실과 날짜를 확인합니다.
2. 사용 허락이 필요한 미디어는 허락 범위를 먼저 확인합니다. 출처 표기만으로 이용허락이 되지 않습니다.
3. SOURCES에 URL/발표 주체/확인일을 추가하고 RECORDS에 새 고유 ID를 추가합니다.
4. 멤버 ID, 관련 기록 ID를 연결합니다. 사실에 근거 없는 세부 프로필·밈·추측은 추가하지 않습니다.
5. develop에서 npm test, npm run build, 브라우저 검토를 거칩니다.
6. 사용자 검토 후 main PR로 운영 반영합니다.

## 비공개 제보를 공개 저장소에 두지 않기

이 저장소는 공개입니다. draft 플래그만 붙여도 JS 파일이 내려가면 내용이 노출됩니다. **미검수 제보·권리 증빙·개인정보를 이 저장소 어디에도 저장하지 마세요.** 공개 번들에는 published 상태만 허용하며 검증기가 다른 상태를 거부합니다. 향후 CMS 도입 시 비공개 저장소와 인증된 검수 화면이 필요합니다.

## 수정·삭제

항목 삭제 시 RECORDS에서 제거하고 모든 related 참조를 함께 정리합니다. 빌드 검증이 누락된 연결을 발견합니다. 앱은 저장된 즐겨찾기 중 사라진 ID를 자동 제외합니다. 원본 접근 불가는 복원·재배포의 근거가 아닙니다. 삭제 요청을 받으면 공개 검색/본문/연관 링크/미리보기를 함께 제거합니다.

Git 이력과 외부 임시 CDN은 별개입니다. 민감한 내용을 애초에 커밋하지 않는 것이 우선이며, 잘못 공개된 정보는 저장소 이력 정리와 CDN 무효화/제거 요청을 별도 수행해야 합니다.
