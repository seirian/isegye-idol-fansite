# 음반 1차 검토 — feature/albums

## 검토 범위

운영 `main`과 음악 UI를 교체하지 않는 독립 검토판. 기존 관리자 Google 로그인과 점검 모드 정책 뒤에서 `/review-albums/` 및 `/review-albums/api/insights`를 제공한다. 게스트와 일반 회원은 검토 화면/API에 접근할 수 없다. 기존 1·2차 검토판은 유지한다.

음반 목록은 카드/리스트 전환, 수록곡까지 검색, 멤버·연도·메타데이터 연결 범위 필터, 최신/제목/연결 범위 정렬을 제공한다. 음반별 수록곡 길이 미니 그래프는 순위 그래프와 구분한다. 상세는 가로형 곡 헤더, 핵심 지표, 공식 영상 비교, 한 개의 선택형 순위 그래프, 수록곡 길이 비교, 트랙 이동, 간결한 서비스 연결 패널로 구성한다. 원본 차트 사이트의 이미지·코드·가사·순위 데이터를 복제하지 않는다. 타일은 자체 그래픽이며 공식 커버가 아니다.

## 실제 API와 제한

- Apple iTunes Search API: 미국(US) 카탈로그. 한국 검색은 결과가 없어 US 메타데이터를 사용한다. 아티스트·제목/검증된 제공처 표기·앨범을 대조하고 유일한 음원 ID만 연결한다. 첫 검증에서 대상 21곡 중 유통 음원 19곡을 연결했다. 영상 공개용 2곡에는 음원 정보를 억지로 붙이지 않는다. 장르/재생시간/원본 링크와 국가를 표시한다.
- YouTube Data API `videos.list`: 기존 `ISEGYE_YOUTUBE_API_KEY`를 서버 수집에서만 사용한다. 기존 검증된 `catalog/video-sources.tsv`의 공식 영상 20개에 공개 조회수/좋아요를 연결한다. 팬 백업은 공식 영상 통계에서 제외한다. 숫자는 수집 시점의 스냅샷이다.
- Apple 한국 most-played TOP100: 제공처 응답·갱신 시각·국가·100개 완전성을 검증한다. 시간 초과/실패는 실패로 표시한다. US 음원 ID가 KR 차트에 없다는 이유만으로 차트 밖이라고 판단하지 않는다. KR 차트에서 동일 ID를 실제로 확인해야 순위 이력을 연결한다.
- 멜론·지니·벅스·FLO·Spotify 지표: 승인된 데이터 제공 방식/정확한 음원 ID가 준비되지 않아 미연동 상태를 명시한다. 직접 연결과 검색 링크를 구분한다. 비공식 내부 API나 robots 제한을 우회하지 않는다. 멜론 좋아요·역대 최고 순위·가사를 임의로 생성하지 않는다.

API 참고: https://performance-partners.apple.com/search-api ; https://developers.google.com/youtube/v3/docs/videos/list ; https://rss.marketingtools.apple.com/api/v2/kr/music/most-played/100/songs.json

`cat-save-world`의 Apple 표기는 `NO CAT, NO LIFE!`이다. 고세구, 동일 음반, 트랙 1, 발매일, 175초 및 유통사 트랙 목록을 대조한 별칭이다. 한국어 제목 자체는 기존 카탈로그를 유지한다. 겨울봄/Winter Spring, 화이트/White도 제공처별 표기만 대응한다.

## 그래프 원칙

실제 조회수/좋아요 비교와 재생시간 막대는 API 응답값만 사용한다. 순위 축은 1위가 위쪽이고 시간 간격을 보존한다. 수집 실패·차트 밖은 선을 끊고, 데이터 1개는 점 하나만 그린다. 24시간/7일/30일은 조회 구간이며 그 기간 전체의 데이터가 있다는 뜻이 아니다. 관측 최고는 선택 기간 내 수집분의 최고로, 역대 최고가 아니다. 키보드 포커스와 수치 표 대안을 제공한다.

순위 이력이 아직 없는 상태에서도 UI 검토가 가능하도록 `그래프 예시 보기`를 제공한다. 이 모드는 URL의 `demo=1`로만 켜지고 `예시 데이터 · 실제 순위가 아닙니다`를 표시하며 실제 API 데이터/캐시를 변경하지 않는다.

## 수집과 게시

`.github/workflows/albums-preview.yml`은 feature/albums push 또는 수동 실행에서만 동작한다. 기존 운영 일배치/월배치는 변경하지 않았다. 별도 기능 브랜치 캐시에 공개 관측값을 보관하므로 수동 재실행 시 이전 확인분을 이어갈 수 있다. 캐시는 영구 데이터베이스가 아니며 운영 전에는 승인된 제공처, 영속 저장, 수집 주기, 보존 정책을 별도 확정해야 한다.

브라우저는 외부 비밀키를 갖지 않고 동일 출처의 관리자 전용 읽기 API를 호출한다. API 오류 시 내장된 동일 버전 검토 스냅샷을 표시하며 실패 상태를 알린다. API 응답과 HTML은 릴리스 해시로 확인한다. 검토판은 noindex/no-store, 해시 기반 CSP, 독립 localStorage 네임스페이스를 사용한다.

`npm test`, Python 수집 테스트, 320/390/768/1440px 브라우저 테스트와 기존 인증 회귀 테스트를 통과한 정확한 산출물만 게시한다. 게이트·API·변조/심볼릭 링크 차단·로그아웃·기존 검토판 보존을 검사한다. 실제 Google 계정으로 자동 로그인하지 않는다. 로컬 TLS의 합성 계정으로 권한 흐름을 검사하고 원격에서는 파일 해시와 비로그인 차단을 검증한다.

게시 스크립트는 기존 SSH 호스트키·사이트 소유 마커·전역 배포 잠금을 확인한다. 비공개 검토 폴더, 변경 불가 형식의 인증 런타임 사본, 관리 진입점만 갱신한다. 운영 HTML/JS, 공유 라우터, 다른 사이트 응답, 계정 저장소, 기존 검토판을 교체하지 않는다. 실패하면 기존 진입점과 검토 포인터로 되돌린다. `review-albums-deployment.json`이 실제 게시 여부의 기준이다. 환경 이름 production은 기존 호스팅 자격증명 범위이며 운영 음악 UI 배포를 뜻하지 않는다.
