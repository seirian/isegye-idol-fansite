# 홈 검토안: LIVE 유지, 콘텐츠를 바로 찾는 첫 화면

## 결정

기존 분위기를 없애는 리뉴얼보다 **LIVE 그대로 + 아래 영역의 우선순위 재정리**를 제안합니다. 최상단 LIVE의 HTML 생성 함수, 상태 처리, 30초 갱신과 방송 썸네일을 변경하지 않습니다. 실시간 상태를 좋아한다는 운영자의 추가 요청을 우선합니다.

현재 코드는 큰 슬로건·단체 그림·6개 대형 포토카드 뒤에 구형 음반 레코드 3개를 `오늘의 플레이리스트`로 표시하고, 이미 메뉴에 있는 LIVE/활동 기록/가이드로 다시 안내합니다. 별도 활동 블록도 고정된 과거 기록 3개입니다. 방문 통계는 없으므로 낮은 클릭률을 입증한 진단이 아니라, 실제 코드와 운영자 피드백에 따른 구조상 가설입니다.

## 제안한 순서

1. **LIVE 그대로**: 들어오자마자 방송 상태 확인.
2. **짧은 소개 + 멤버 바로가기**: 단체 그림을 작게 유지하고 프로필6개는 압축. 첫 방문자는 멤버 소개, 기존 팬은 이름으로 바로 이동.
3. **최근 영상3개**: 본채널·음악 채널에서 공개일 순. 전체/멤버 필터. VOD가 첫 화면을 독점하지 않게 홈에서 제외하되 상세의21개 채널은 유지. 수집 확인일을 공개하며 실시간 수집이라고 표현하지 않음.
4. **음악3개**: 오리지널/커버/리메이크 전환과 전체154개 진입. 같은 음반은 대표1곡, 공식MV를 동률 우선. 공식/팬백업/노래방 구분 유지. 개인화·오늘의 추천이라고 표현하지 않음.
5. **소식·일정 / 활동 기록**: 큰 홍보 블록 대신 짧은 두 바로가기. 확인된 향후 일정이 없으면 과거 일정을 다음 일정으로 재사용하지 않음.

추상적인3개 제목, 중복 탐색 타일과 커다란 제보 배너는 제거합니다. 소개 페이지의 `함께 채우는 기록`도 출처 안내로 변경합니다. 권리·오류정정 창구는 별개의 운영 안전장치라 푸터에 유지합니다. 그 밖의 오래된 문서/접수 경로를 전면 폐기하는 작업은 이번 범위가 아닙니다.

## 자동수집 방향

방문자에게 자료를 제출하라는 요청을 하지 않는 탐색형 홈입니다. 기존 SOOP 상태조회와 YouTube 공개 피드 빌드 갱신을 재사용했습니다. **왁물원 크롤러, 자동 검수·동기화 서비스, 예약 수집은 이번에 만들지 않았습니다.** 추후 공개 원문 수집 → 원문ID/URL로 중복제거 → 멤버/유형/발생일/게시일 구분 → 검증된 데이터 저장 → 홈 요약 구성으로 연결하는 것을 권합니다. 수집 실패를 새 정보 없음/방송 없음으로 바꾸지 않고 마지막 성공 시각과 미확인 상태를 유지해야 합니다. 접근 제한 게시물은 자동 공개 자료처럼 취급하지 않습니다.

## 비교와 범위

새 분리 브랜치 `feature/home-simple`, 새 경로 `/previews/feature-home-simple/`로 검토합니다. main/develop/기존LIVE브랜치와 운영 SFTP 배포 파일은 수정하지 않습니다. 프로토타입은 v0.4 빌드에 홈만 적용하는 별도 빌더로 noindex를 강제합니다. 비교용 기존 개발홈과 기존 검토 경로를 같이 게시합니다. 이후 develop이 자기 기존 워크플로로 재게시하면 신규 경로는 다시 빠질 수 있으므로, 공통 다중프리뷰 게시 구조는 별도 반영이 필요합니다.

단순한 포털식 텍스트 링크만 두는 안은 빠르지만 이미 채택한 아이돌 팬사이트 개성을 약화시켜 제외했습니다. 모든 공지·영상·기록을 한 피드에 섞는 안도 첫 화면을 다시 복잡하게 하므로 제외했습니다. 이 안은 기능적 제목을 사용하되 이미지·파스텔·멤버색은 유지합니다.
