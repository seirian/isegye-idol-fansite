# 놀이터: 실제 신규 문제 확보와 지문 교정

## 2026-11-24 정비

기존 매일 08:00 KST 예약은 유지한다. 실행 성공과 문제 증가를 구분한다.
검수 대기열·교정 목록·수집 및 게시 코드 변경이 main에 반영되면 즉시
검증 갱신한다. 정기/수동/변경 반영 실행은 같은 일일 예산과 잠금을 공유한다.
공식 원본 검증 문제에 더해 코드 검토를 거친 `playground/reserve.json`의
고정 출제 대기열을 사용한다. 일일 목표는 4문제이며 기존 절대 상한 8문제와
전체 1,000문제 상한도 유지한다. 같은 날 재실행으로 목표를 초과하거나
같은 사실을 중복 추가하지 않는다. 다음 한국 날짜부터 오늘의 퀴즈 후보가
되므로 이미 시작한 오늘의 다섯 문제와 브라우저 기록은 변하지 않는다.

초기 대기열은 68문제(음악 9, 멤버 7, 무대/활동 10, 커버 42)다.
이것은 무한한 문제 생성 기능이 아니다. 공개 자료가 없으면 검증되지 않은
문제를 만들지 않으며, 대기분 부족/소진을 경고한다. 등록된 보존 자료의
확인 날짜와 근거 한계를 그대로 유지한다. 최근 원문 재열람이나 공식
검증을 수행한 것처럼 날짜와 출처 등급을 바꾸지 않는다.

## 매일 실행

1. 소유권, 기존 라우터, 스키마를 확인하고 현재 문제은행을 복원한다.
2. 공식 자료는 최대 20개만 검증한다. 시작 위치를 날짜별로 회전하여 앞의
   실패 항목이 뒤 후보를 계속 가리지 않게 한다.
3. 부족분은 검수 대기열에서 주제 순환 방식으로 고른다. 기존 ID, 정규화한
   지문, 사실 키, 이미 사용한 원본 영상은 제외한다.
4. 모든 추가 문제의 정답/보기/출처를 고정 승인 항목과 다시 비교한다.
   외부 커뮤니티 글은 검토함에만 넣으며 자동 정답으로 게시하지 않는다.
5. 후보와 일별 증설 이력을 같은 파일에 원자적으로 게시하고 서버에서
   다시 읽어 검증한다. 기존 잠금, 동시 수정 검사와 롤백을 유지한다.

`growth`에는 오늘 신규 추가, 이번 실행 추가, 마지막 실제 추가 시각,
검수 완료 대기 문제, 4문제/일 기준 대기 일수, 연속 추가 0일, 일별 이력
최대 90개를 남긴다. 도입 이전의 신규 추가 이력은 추정하지 않는다.
동일 날짜 재실행은 그날의 합계를 유지하며 0일 수를 더하지 않는다.

## 경고와 관리자 화면

- 3일 연속 추가 0건, 검수 대기열 소진, 전체 상한 도달은 공급 장애다.
- 대기 문제 28개 미만은 7일 미만 준비분 경고다.
- GitHub 이슈는 동일한 제목으로 한 건만 생성한다. 열린 동안 반복 생성,
  댓글 또는 매 실행 본문 수정을 하지 않는다. 실제 신규 게시와 준비분
  회복이 모두 확인되면 닫는다.
- 일시 중지나 게시 재조회 실패는 증설 복구로 오인하지 않는다.
- 모니터링에서 게시 검증 상태와 문제 공급 상태를 분리한다. 공급 경고를
  이유로 성공 배치를 계속 다시 실행하지 않는다. watchdog의 게시 성공
  판단 기준과 관리자 접근 권한은 변경하지 않는다.

## 안전한 문구 정비

`playground/editorial.json`은 22개의 승인된 before/after 지문을 보관한다.
저장된 기존 기본 문제와 누적 피드의 원본 바이트는 유지한다. 운영 화면은
엄격한 피드 검증을 먼저 통과한 뒤, 빌드에 포함된 승인 지문만 교정하여
표시한다. 외부 피드가 교정을 승인할 수 없다. ID, 보기, 정답, 상태, 출처,
출제 가능일, 저장 버전은 변경할 수 없다. 현재 문장이 before와 다르면
승인되지 않은 수정으로 거부한다. 커뮤니티 답안 문제는 질문 위 배지와
해설에 그 기준을 별도로 표시한다.

## 대기열 보충 방법

새로운 사실마다 `subject`와 `predicate`를 명시하고 출처/확인 시점을
보존한다. 채널 주인만 확인한 영상에서 가창자, 가사, 발매일 등을 추론하지
않는다. 기존에 승인한 대기열 항목은 게시 후에도 삭제하거나 변경하지
않는다. 사실 수정은 별도 교정 검토가 필요하다. 수량을 맞추기 위해 기존
질문을 말만 바꿔 새 문제로 등록하지 않는다. `playground-review-inbox.json`
은 후보 자료와 분야별 대기 수를 제공하지만 자동 승인 파일은 아니다.

검증: `python scripts/build_playground.py`,
`python -m unittest discover -s tests -p 'test_playground*.py' -v`,
`node --test tests/playground*.test.js`, 관리자 모니터링 회귀 검사와 기존
운영 배포의 브라우저/접근 차단 검사를 통과한 뒤 게시한다.
