- 배포 메타데이터의 `courierGame`에 검토 승인 커밋·운영 경로·저장 키·게임 및 그림 체크섬을 기록한다. 브라우저 검사는 놀이터 진입, 캐릭터 선택·키보드·터치 조작, 복귀 후 퀴즈 진행 보존을 확인한다. 실제 로컬 TLS/PHP의 가상 계정 검사로 신규 경로의 기존 접근 정책도 확인한다.

승인된 검토 커밋: `4583f8e1e460da0b1fc45967a010bd41e2f336b3`.
운영 메뉴: `/#/playground`. 기존 운영 헤더·하단 메뉴·계정 정책을 유지하고, PC 메뉴와 모바일 더보기에 놀이터를 추가한다. 승인한 퀴즈 화면은 CSS가 다른 메뉴에 영향을 주지 않도록 격리해서 사용한다. `main`과 `develop` 병합은 이번 사용자 요청으로 승인됐다.

## 운영 화면

기존 32문항, 오늘의 다섯 문제, 주제별 퀴즈, 발매 순서 맞히기, 해설·참고 출처·내 기록을 유지한다. 운영 기록 키는 `isegye:playground:v1`, 검토 기록 키는 기존 값을 유지하므로 섞이지 않는다. 문항은 누적 추가하고 기존 정답은 자동 변경하지 않는다. 따라서 매일 문제은행이 갱신되어도 진행 중 풀이와 완료 기록을 초기화하지 않는다.

`/api/playground`에서 데이터만 읽는다. API는 기존 회원·관리자·공사중 접근 정책을 그대로 적용한다. 수집 장애나 손상 시 배포 시 검증한 기본 32문항으로 이용할 수 있으며, 기본 데이터 표시를 알린다. 외부 자료는 브라우저에서 직접 수집하지 않는다.

## 별도 일배치

- 워크플로: `playground-daily.yml` / Playground - daily verified question bank.
- 예약: 매일 **08:00 Asia/Seoul** (`0 23 * * *` UTC), 하루 1회. GitHub 예약은 정확한 시각 실행을 보장하지 않는다.
- 추가 자동 실행 없음: 운영 배포 완료 및 소스 검사 성공에 따른 추가 갱신을 제거했다. 명시적 수동 workflow_dispatch는 유지하며, 실패·누락만 기존 복구 제한 안에서 재시도한다.
- 독립 중단 변수: `ISEGYE_PLAYGROUND_PAUSED`; 전체 `PRODUCTION_PAUSED`도 준수.
- 기존 배포와 같은 직렬 실행 그룹을 사용해 동시 쓰기를 피한다.
- 기존 watchdog에 일배치 슬롯과 **서버 읽기 재확인 산출물** 검증을 등록한다. 실패/누락은 기존 제한된 재실행·배치 이슈 경로에서 다룬다.

### 자동 반영과 참고 후보의 구분

1. 운영 서버의 누적 문제은행과 기존 검증 음악 피드를 복원한다. 계정·세션·개인 저장함은 읽지 않는다.
2. 기존 음악 수집이 검증한 새 영상과 카탈로그의 공식 채널 후보를 대상으로, 당일 YouTube 공개 oEmbed에서 **공식 채널 주소와 영상 제목**을 다시 대조한다. 현재 자동 출제 유형은 사실 확인이 가능한 **공식 영상의 멤버 채널 맞히기**이며, 영상 공개를 음원 발매로 바꾸지 않는다. 자동으로 팬문화·방송 에피소드의 답을 추측하지 않는다.
3. 같은 작품·멤버·유형의 중복을 막고 하루 최대 8문항을 누적한다. 반복 실행해도 하루 한도를 넘지 않는다. 새 문항은 주제별 자유 퀴즈에는 바로 들어가고, ‘오늘의 문제’에는 다음 한국 날짜부터 포함하여 당일 문제 구성이 바뀌지 않게 한다.
4. 기존 네이버 검색 API 설정으로 이세돌 퀴즈·정답 글을 찾고, 지정된 두 참고 글도 다시 확인한다. 공개 렌더링 본문까지 읽으며 검색 요약만으로 확인 처리하지 않는다. 본문 체크섬·문항 표시 수·답안 영역 유무·변경 여부를 후보 기록에 보관한다. **원문 문제집을 복제하거나 커뮤니티 답안을 자동 출제하지 않는다.** 신규 팬문화 문제는 답안 대조·수정 댓글·시점 검토 후 씨드에 별도 반영한다. 직접 열람이 실패하면 실패로 기록하고 최신 확인으로 가장하지 않는다.
5. 검증을 통과한 누적 JSON만 고유 폴더 `.playground-bank`에 게시한다. 이전 스냅샷을 보관하고 서버 재확인에 실패하면 이전 포인터 내용으로 복구한다. 새 문항이 없어도 매일 확인은 수행하지만 새 문항을 억지로 생성하지 않는다.

초기 자동화는 위 범위이며 ‘인터넷의 모든 퀴즈를 매일 완전 수집’하는 기능이 아니다. 나무위키 기반으로 이미 검토한 씨드 자료와 공식 출처 연결은 유지하지만, 보안 확인 화면을 우회해 위키 본문을 수집하지 않는다. 정답 수정/철회 등 비호환 변경은 검토 후 별도 버전 배포로 처리한다.

## 배포·검증

main의 기존 production 워크플로 마지막 구성 단계에서 놀이터를 합성한다. 원래 검토 경로 4개와 `/review-playground/`는 그대로 보존하며 구 검토 브랜치의 자동 배포만 종료한다. 팬메이드 메뉴는 운영에 추가하지 않는다.

검증: 전체 JavaScript 단위 테스트, Python 검증, 누적/중복/하루 상한/중단/롤백 테스트, 실제 HTTP 운영 SPA에서 메뉴·이어풀기·결과·공유·모바일 검사, 실제 로컬 TLS/PHP의 가상 계정으로 API 접근 정책·손상·심볼릭링크·회원정보 비노출 검사. 실제 회원의 Google 로그인을 대신하지 않는다.

## 검색 API 재점검 (2026-11-17)

첫 운영 배치에서 8문항 추가 및 총 40문항 서버 읽기 재확인은 성공했으나, 신규 카페 검색이 옛 OpenAPI 주소를 참조해 실패했다. 지정된 두 공개 게시글 본문은 정상 확인했다. 수집기를 기존 `schedule_feed.request`의 NAVER API HUB 주소·NCP 인증 헤더·리다이렉트 차단·안전한 오류 코드 처리에 통일했다. API 키를 옛 주소나 공개 oEmbed 읽기로 보내지 않는 회귀 테스트를 추가했다.

`playground-bank-checks.yml`은 수집기 관련 변경 시 인증정보 없는 단위 검사 후 기존 검색 API로 읽기 전용 확인을 수행한다. 2026-11-17 일정 변경 이후에는 검사 통과만으로 `playground-daily.yml`을 추가 요청하지 않는다. 정기 갱신은 08:00 하루 1회이며 검사 워크플로는 읽기 전용이다. 운영 UI와 배포 정책, 기존 배치/회원 데이터는 변경하지 않는다.

실제 게시된 40문항의 체크섬과 일치하는 데이터로 추가 검증하면서, JSON 정렬이 주제 순서를 바꾸어 오늘의 문항 추첨 순서에 영향을 줄 수 있음을 확인했다. 게시 JSON만 승인된 씨드의 주제 순서를 유지하도록 직렬화한다. 데이터 체크섬·기존 문항·정답은 바뀌지 않으며 이미 진행 중인 풀이도 유지한다. 문제은행 저장 후 재읽기와 하루 추첨 안정성 회귀 검사를 추가했다.

- 참고 자료 전체 안내는 페이지 오른쪽 하단의 관리자 전용 링크로 이동했다. 서버 세션의 권한 확인 뒤 별도 `/src/playground-admin.js`를 읽으며, 일반 회원·비로그인 사용자의 직접 모듈 요청도 서버에서 차단한다. 권한 만료·조회 실패 때 열린 안내도 닫는다. 문제를 푼 뒤의 정답 해설·개별 출처는 유지한다.
- 승인 기본 문제은행은 80문항: 음악 20 / 멤버 20 / 커버 22 / 무대 이야기 18. 기존 32개 문항을 수정하지 않고 48개를 추가했다. 기존 자동 추가 8개가 있는 서버는 총 88개로 확장하며 이후 일배치도 그대로 누적한다.

- 예전 32개 기본 자료를 `playground/seed-v1.json`으로 보존해 엄격한 호환 검사를 한다. 기존 40개 누적 문항, 정답, 문제 ID, 저장 버전, 그날의 자동 추가 상한을 유지하며 승인된 48개만 덧붙인다. 일배치가 실행되기 전에도 서버 API가 기존 자동 문항을 보존한 채 새 기본 문제를 합친다.
