# Google access 운영 활성화

사용자가 등록한 저장소 변수 ISEGYE_GOOGLE_CLIENT_ID를 main의 production 환경에서 읽습니다. 기존 SFTP secret과 호스트키 검증을 재사용합니다. 비밀번호·토큰·회원원장을 아티팩트나 로그에 포함하지 않습니다.

## 활성화 조건
- 기존 비공개 회원 원장과 사이트 키를 읽고 검증합니다. 원장/키가 없으면 초기화하지 않고 중단합니다.
- 빈 Client ID만 설정하며 다른 값으로 교체하거나 siteKey/adminEmailDigest를 회전하지 않습니다.
- 최초 Google 로그인은 사용자가 직접 수행합니다. 운영에는 테스트 계정·서명키·로그인 세션을 만들지 않습니다.
- 지정 Google 계정이 검증된 첫 가입에 성공한 후에만 공사중입니다. 그 전에는 기존 홈이 공개됩니다.

## 배포와 복구
`deploy_google_access.py`는 `/web/_isegye_idol` 안에서만 작동합니다. 공개 파일은 새 릴리스에, PHP 코드는 비공개 불변 런타임에 둡니다. `/access.php`와 이세돌 전용 `.htaccess`가 모든 요청을 서버 권한 검사로 보냅니다. 오래된 릴리스 URL과 비공개 경로도 콘텐츠를 노출하지 않습니다.

이후 main 배포 역시 같은 gateway를 유지합니다. 실패 시 이전 콘텐츠 릴리스로 돌아가더라도 인증 게이트는 유지합니다. 첫 활성화에서조차 정적 공개 라우터로 자동 복구하지 않습니다. 회원 가입과 배포가 겹쳐도 관리자 가입 조건을 무효화하지 않습니다. 기존 정적 배포 스크립트는 새 라우터를 인식하지 못해 쓰기 전에 중단합니다.

## 검토 사이트
GitHub Pages는 기존 검토 경로를 운영 도메인 안내로 대체합니다. 공사중이라는 문구를 미리 표시하지 않고 실제 접근 상태는 운영 서버가 결정합니다. 앱 JS/회원 정보/콘텐츠 카탈로그를 Pages 산출물에 넣지 않습니다. 과거 feature 전용 게시 워크플로도 비활성화해야 다시 공개 미러가 생기지 않습니다. 공개 GitHub 소스와 이미 받은 캐시까지 비공개로 바꾸는 조치는 아닙니다.

## 검증 범위
회원 저장57/JWT24/로컬 TLS50 검사를 유지합니다. Python 검사는 라우팅·설정 보존·접근제어 유지 복구를 확인합니다. 운영 검사는 비로그인 상태, 로그인 페이지, Google 공식 버튼과 가능한 경우 Google 계정선택 화면까지 확인하며 자격증명을 입력하지 않습니다. 첫 실제 Google 로그인 결과는 사용자 가입 이후 별도입니다.

결과는 `auth-deployment.json`과 `test-results/google-access-live/result.json`에 계정 식별값·쿠키·토큰 없이 기록합니다. PHP 회원 원장에는 HMAC 식별키와 권한만 저장됩니다. 비활성 stage는 자동 실행에서 제거했고 운영 활성화는 main 전용 production 작업에서만 실행합니다.
