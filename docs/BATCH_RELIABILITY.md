### 변경 내용
- 기존 5개 배치 cron, 제어기의 12/32/52분 cron, 5분 유예, 15분 쿨다운,
  rolling 1시간당 워크플로별 최대 2회 dispatch, 공통 운영 쓰기 잠금은 그대로다.
- main의 앨범/공지/Production 완료 이벤트로 제어기를 추가 호출한다. 제어기 자신과
  PR/포크 워크플로는 대상이 아니다. 이벤트와 REST run의 저장소/브랜치/경로/상태를
  재검증하며 checkout은 여전히 고정 main이다. 이벤트의 코드나 아티팩트를 실행하지 않는다.
- 최신 생성 10건만 검사하던 조회를 검색 필터 없이 페이지당 100건, 최대 20페이지로 확대한다. main 여부는 로컬에서 검사한다.
  페이지를 끝까지 검증한 뒤 최신 attempt 시각으로 정렬한다. 범위 초과/불완전 조회는
  `inspection_failed`이며 dispatch하지 않는다. 오래된 run의 최근 재실행을 놓치지 않는다.
  실행 기록량이 상한에 접근하면 조회 설계를 재검토한다. 상한을 조용히 무시하지 않는다.
- dispatch 직전에는 active만 보지 않고 게시 근거, 쿨다운, 시간당 상한, 현재 슬롯을
  다시 계산한다. 읽는 도중 슬롯/새벽 경계를 넘으면 `slot_changed`/`night_pause`로 멈춘다.
- 이미 현재 회차가 정상인데 과거 차트 공백만 남은 경우는 historicalGapsOnly 경고로
  남기되 현재 장애 이슈를 반복 생성/갱신하지 않는다. 과거 순위를 만들지 않는다.
- active/cooldown/grace는 요약 `pending`이며 게시 완료가 아니다.
- 공지는 기존 바이트 단위 서버 재조회 검사를 유지하면서 publishedAt, readbackAt,
  verifiedReadback을 보고서에 기록한다. 재조회 불일치 시 성공값을 생성하지 않는다.
  과거 보고서는 기존 검증 방식과 호환하되 명시적인 false 값은 성공으로 인정하지 않는다.

### 남는 근본 제약
완료 이벤트는 실행이 하나라도 있어야 발생한다. GitHub 예약 이벤트가 모두 누락되면
이 보완만으로 정각 복구를 보장할 수 없다. 독립된 시간 기준의 점검은 여전히 필요하며,
필요할 경우 별도 승인을 거쳐 독립 스케줄러가 현재 main의 검증된 제어기만 호출해야 한다.
외부 점검은 현재 공지 슬롯의 +5분(:10) 이후 결과를 확인한다. 유예 종료 직전에 제어기를
반복 실행해 쿨다운만 발생시키지 않는다. 기존 자동화/토큰/계정 설정은 이 패치에서 바꾸지 않는다.

### 검토안 적용 시 추가 보강
- branch/status/created 검색 필터의 1,000건 제한을 피하도록 워크플로 전체 이력을 페이지 조회한다.
  비-main 이력은 페이지 수에는 포함하되 복구 판단에서 제외한다. 조회 도중 전체 건수 변경,
  중복 ID, 알 수 없는 상태, 잘못된 attempt, 재실행 시작 시각 누락은 실패 처리한다.
  20페이지의 명시적 예산은 유지하고, 초과 시 완전 조회라고 주장하거나 보충 요청하지 않는다.
- 아티팩트 목록도 페이지 단위로 확인한다. ZIP 크기/해시, 확장된 증거의 합계 크기,
  심볼릭 링크와 JSON 자료형을 검사한다. 일부 조회 오류를 자료 없음으로 숨기지 않는다.
- 신규 공지 보고서는 evidenceVersion=2이다. 명시적인 true 및 생성→게시→재조회 시각의
  순서·시간대를 검증한다. 구버전 보고서는 legacy_report로 구별하며 새 재조회 증거로 간주하지 않는다.
- 신뢰할 수 없는 완료 이벤트는 어떤 작업도 요청하지 않고 inspection_failed 보고서를 남긴다.
  장애 이슈 API 실패도 성공 상태로 숨기지 않는다.
- 저장소 전체 CI 통과와 main 병합 뒤의 실제 수집/게시/배포 검증은 별도로 기록한다.
  이 문서의 코드 수정 설명만으로 정각 실행 보장이나 운영 복구 완료를 주장하지 않는다.
