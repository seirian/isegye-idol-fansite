# 소식·일정 카페 갱신과 수집 상태

2026-11-04 요청 반영. 카페 입력이 11월 2일 게시글에서 멈춘 문제와 브라우저가 빌드 당시 URL 목록에 없는 새 글을 버리던 문제를 함께 수정한다.

## 시간배치

`main`의 `schedule-refresh.yml`은 매시간 05분 예약이며 명시적 수동 실행을 지원한다. 운영 배포 후 추가 실행은 제거했다. 예약 실행은 지연될 수 있다.

1. 중지 설정 확인, 데이터 규칙 검사, 검색 API의 미검증 집계 신호 확인.
2. 배포 자격 증명이 없는 별도 단계에서 기존 공개 브라우저 검증기를 실행한다. 승인된 두 게시판(345, 1250)과 지정 원문과 같은 작성자·게시판의 뱅온 시리즈만 대상으로 한다. 최근 완료된 3일과 오늘을 중복 확인하고 최대 8페이지·14일 제한을 유지한다. 로그인이나 직접 Cafe 내부 API 호출을 추가하지 않는다.
3. 작성자·권한·게시판·공개 여부·원 게시일이 확인된 메타데이터만 게시 프로그램에 전달한다. 검색 후보는 공지로 승격하지 않는다. 팬 정리는 방송 확정이 아니다. 일반 작성자 글·댓글·원문 전체는 저장하지 않는다.
4. 검증 근거 `cafeEvidence`를 기존 비공개 일정 스냅샷 안에 누적한다. 새 원문은 재배포 없이 표시하되 제목·멤버·게시일·출처가 검증 근거와 일치해야 한다. 잘못된 근거는 거절하고 마지막 정상 화면을 유지한다.
5. 기존 잠금·원자 교체·읽기 검증으로 `current.json`과 `previous.json`을 갱신한다. 인증·라우터·타 사이트 파일은 변경하지 않는다.
6. 게시 후 필수 출처별 갱신 성공과 최근 3시간 이내 원본 확인을 검사한다. 실패·미확인·오래된 관측·미보충 수집 공백이면 Actions를 실패 처리한다. 게시 성공과 수집 완료는 별개다.

## 관측과 보존

`publishedAt`은 원 게시 시각이다. `checkedAt`과 `lastSuccessAt`은 실제 원본 확인 시각이며 실패한 자료를 새로 확인한 것으로 바꾸지 않는다. 일부 출처 실패 시 기존 검증 자료를 보존한다. 최근 구간 밖의 수집 공백은 `gapFromKst`와 `gapThroughKst`로 유지하고 해당 기간을 실제로 검증한 뒤 해제한다. 명시되지 않은 방송 시각은 추정하지 않는다.

## 보고서

- `schedule-publication.json`: 서버 게시 상태, 출처별 수집 상태, 한국 날짜별 멤버 공지 건수, 누적 검증 근거 건수.
- `schedule-health.json`: 게시 성공과 출처 갱신 완료를 분리한 최종 판정.
- `cafe-window.json`: 이번 실행이 확인한 제한된 공개 구간과 메타데이터.
- `cafe-discovery.json`: 검색 집계 신호. 게시판 전수 확인이나 누락 개수의 증거가 아니다.

`complete`는 설정된 공개 확인 범위의 필수 출처가 갱신됐다는 뜻이며 과거 전수 수집이나 팬 정리의 실제 방송 확정을 뜻하지 않는다. 베리즈 공지 첫 목록과 팬 시리즈의 제한된 확인 범위는 별도로 남긴다. 수동 `cafe-approved-window.yml`은 특정 누락 기간 보충용으로 유지한다.
