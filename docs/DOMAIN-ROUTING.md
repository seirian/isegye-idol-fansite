# 이세돌 도메인 조건부 연결

사용자가 2026-10-21 승인한 방식: 기존 공용 `/web/.htaccess` 내용을 그대로 두고 `isegye-idol.kr` 요청만 `/web/_isegye_idol`에 연결합니다. 일반 앱 배포는 이세돌 폴더 내부로 제한됩니다.

- 기존 `/web/_mir_site` 파일과 미르 저장소는 변경하지 않습니다.
- 초기 감사의 원본 SHA-256과 다르면 적용하지 않습니다. 같은 규칙은 중복 삽입하지 않습니다.
- 원본은 이세돌 `.routing-backups`에 보관합니다. 폴더 0700, 백업 0600이며 HTTP 접근을 검사합니다. 원본 본문이나 비밀번호를 로그/아티팩트에 담지 않습니다.
- 이세돌 및 기존 미르 배포 잠금을 함께 획득합니다. 기존 잠금을 강제로 제거하지 않습니다.
- 기존 규칙, 권한, 소유자와 그룹을 보존하고 SFTP 원자적 교체 후 HTTP/HTTPS 고유 시험 파일로 연결을 증명합니다. 실패하면 원복을 시도하되 외부 변경은 덮어쓰지 않습니다.
- 미르 홈·밴드·노래책과 개인 사이트의 응답을 변경 전후 비교합니다. 밴드의 정상 `/band` → `/band/` 301 이동과 목적지 200을 각각 확인합니다.
- 다른 호스트의 이세돌 시험 파일 접근 및 이세돌 호스트의 기존 미르 경로 접근을 차단·검사합니다. 하위 폴더에 독자적인 rewrite 설정이 있어도 지정한 미르 경로를 이세돌 호스트에서 제공하지 않도록 호스트 한정 Require 조건을 사용합니다.
- 시험 파일과 이 작업의 잠금은 제거합니다. `www.isegye-idol.kr`, DNS, 인증서, HTTPS 강제 전환은 이번 범위가 아닙니다.

## 실행

`Configure ISEGYE host-only routing`은 공개 주소 사전 점검 및 자격 증명 없는 로컬 Apache 검사를 실행하고, 성공 후 `production` 환경의 `ISEGYE_SFTP_PASSWORD`로 위 작업만 수행합니다. workflow 파일을 develop에 반영하는 push로 실행됩니다. 보고서의 `status=configured_and_verified`가 실제 완료 조건입니다.

이 작업은 main 병합이나 앱 배포가 아닙니다. 미공개 보호 라우터가 유지된 동안 도메인 홈의 503은 의도된 응답입니다. 실제 검토 화면은 GitHub Pages를 사용하며 main 운영 승격은 별도 절차입니다.

## 복구

검증 실패 시 `rollback_restored_original`을 확인합니다. 수동 복구 시 현재 공유 설정이 보고서의 planned_sha256와 같은지 먼저 확인하고 backup_path의 원본을 원자적으로 복구해야 합니다. 다른 작업자의 후속 변경이나 미르 설정을 덮어쓰지 마세요.
