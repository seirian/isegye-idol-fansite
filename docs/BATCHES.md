# 팬사이트 운영 데이터 배치

예약 시간은 한국시간(Asia/Seoul) 기준이며 실제 시작 시각은 러너 대기에 따라 늦어질 수 있다. 기준: 운영 `main`의 `.github/workflows/`. 2026-11-10 사용자 지정 일정 적용.

예약 시각은 UTC cron으로 변환하며 한국시간 일요일 00시는 UTC 토요일 15시다. GitHub 예약은 정시 시작을 보증하지 않는다.

| 예약 작업 | 실행 예정 | 대상 · 반영 방식 |
| --- | --- | --- |
| 일정·공지 (`schedule-refresh.yml`) | 매시간 05분 (`5 * * * *` UTC) | 왁물원 멤버 공지, 패러블 카페 공지, 뱅온정보의 신규 후보를 검색한다. 검토를 마친 카페 데이터와 패러블 뉴스룸·베리즈 공지·캘린더 자료로 운영 일정 피드를 갱신한다. 검색 신호만으로 카페 글을 게시하지 않는다. |
| 음악 (`music-daily.yml`) | 매일 06:00 (`0 21 * * *` UTC) | 기존 음악 카탈로그의 공식 업로더 9곳에서 최근 공개한 음악 영상을 확인한다. 등록된 영상 링크를 재검사하고 검증을 통과한 새 기록을 운영 음악 페이지에 자동 추가한다. |
| 앨범 정보·차트 (`albums-daily.yml`) | 매시간 00분 (`0 * * * *` UTC) | 등록된 앨범·표지·멜론 차트 관측을 누적하고 필수 출처 검사 및 서버 재조회 후 반영한다. |
| 활동기록 (`history-monthly.yml`) | 매주 일요일 00:00 (`0 15 * * 6` UTC) | 직전 토요일까지의 검증된 공식 소식·음악 공개 기록을 수집하여 기존 연혁에 중복 없이 누적한다. 예정 일정과 실제 활동일은 혼동하지 않는다. |

네 배치는 위 예약과 명시적 수동 실행(`workflow_dispatch`)만 허용한다. 음악·공지의 배포 후 추가 실행 및 음악 성공 후 앨범 연쇄 실행은 제거하여 요청한 주기로만 자동 실행한다. 운영 쓰기는 기존 `isegye-inour-production` 공통 그룹에서 직렬 처리한다. 네 예약 작업과 운영 배포에는 `queue: max`를 적용해 같은 시각 대기 작업이 서로 교체되지 않도록 한다(최대 대기 100개). 일요일 00시 앨범/활동기록 및 매일 06시 앨범/음악이 겹치면 순차 처리되어 실제 시작은 늦을 수 있다. `cafe-approved-window.yml`의 최근 14일 이내 카페 원문 검토·보충은 수동 작업이다. 멤버 채널 21곳의 최신 영상(채널별 최대 3개) 목록 갱신은 빌드·배포 작업이며 음악 일배치와 별개다. 소스 점검용·검토 브랜치용 워크플로는 예약 배치에 포함하지 않는다.

## 음악 등록과 보존

- 대상: 이세계아이돌, 왁타버스, GOSEGU Music, 아이네·징버거·릴파·주르르·고세구·비챤 공식 채널. 채널 ID와 기존 검토된 YouTube 업로더를 함께 확인한다.
- 후보 범위는 공개 피드 또는 채널 영상 탭에 표시되는 최근 업로드 중 30일 이내다. 새 원곡·커버·리메이크는 명시된 표기로만 분류한다. 원곡/리메이크 여부가 명확하지 않은 공식 음원이나 MV는 별도 유형으로 기록한다. 날짜는 영상 공개일이며 음반 발매일로 추정하지 않는다.
- 참여자·제목·영상 ID·게시일과 공개 메타데이터, 썸네일을 검증한다. 동일 영상, 기존 수동 대체 영상, 정규화한 제목과 참여자가 같은 기록은 중복 추가하지 않는다. 반응 영상·쇼츠·티저 등은 제외한다. 팬 백업·노래방 반주의 기존 선정은 유지하되 이들 채널의 새 업로드를 멤버 곡으로 자동 등록하지 않는다.
- 전체 사이트 재배포 없이 음악 데이터만 교체한다. 기존 수동 자료와 이전 검증 데이터를 유지하며, 일시적인 404나 일부 채널 실패를 삭제나 '신규 없음'으로 해석하지 않는다. 접근 방식은 기존 사이트 회원·점검 정책과 동일하다.
- Actions의 `daily-music-*` 결과에는 채널별 성공/오류·검토 대상(`music-discovery.json`), 기존 영상 링크 점검(`source-audit.json`), 추가 수·누계·서버 재검증(`music-publication.json`)이 남는다. 개별 영상 재생 여부나 이용 권한을 보증하는 검사는 아니다. `ISEGYE_MUSIC_PAUSED=true`로 음악 작업을, `PRODUCTION_PAUSED=true`로 공통 운영 작업을 중지한다.

### 공식 그룹 채널: 음악 이외의 업로드 제외

`@isegyeidol_ofcl`은 여러 종류의 채널이므로 공식 채널이라는 이유나 `Highlight` 단어만으로 등록하지 않는다. 아티스트·작품명·형식이 명시된 공식 음원/MV, 앨범 하이라이트 메들리, 음악 스페셜클립을 수집한다. 일반 `Special Clip`은 같은 아티스트의 카탈로그 또는 동일 공식 목록의 오디오/MV에서 곡명이 확인될 때만 허용한다. 보컬·라이브·퍼포먼스가 명시된 음악 스페셜클립도 허용한다. 일반 예능, 뉴스, 티저, 메이킹, 비하인드, 리액션, 쇼츠는 제외한다. 다른 8개 채널의 수집 범위와 06:00 예약은 그대로다.

메들리는 앨범 단위의 영상 기록 한 건(수록곡 발매가 아님), 스페셜클립은 별도 음악 영상이다. 영상 ID는 전역에서 한 번만 등록하며, 서로 다른 포맷이 같은 작품명을 쓸 수 있다. 날짜는 공식 영상 공개일이다. `lFgCjRoFjyU`의 공개 시각은 공식 Atom의 `<published>`에서 2026-11-02T09:00:14Z로 확인했다. 같은 채널·영상 ID·제목을 재확인하는 경우에만 이 값을 재사용하고, 상대 날짜와 음반 발매일은 사용하지 않는다.


### 왁타버스 음악 누락 보충과 검색

왁타버스 `@waktaverse`는 기존 9개 공식 채널의 c1이다. 중복 채널을 추가하지 않고 제목 판별과 과거 보충을 강화했다. 매일 06:00 KST 예약은 유지한다. 최근 30일 신규 조회에 더해 `catalog/waktaverse-history.json`의 검토된 과거 영상 15건도 매번 원문·업로더·oEmbed·썸네일을 확인한다. 실패 시 기존 자료를 보존하고 검토 보류로 남긴다.

확인한 공개 영상 ID 134개에서 관련 후보 44개, 음악 26개(기존 11개, 누락 15개)를 선별했다. 전체 과거/비공개 영상에 대한 완전 수집 보증은 아니다. 명시적인 멤버 참여 음악·MV·협업/피처링·CM송과 확인된 곡의 공연/재즈 버전만 허용하고 타 출연자만의 노래, 티저, 안무, 쇼츠, BGM, 예능, 리액션은 제외한다. 협업 원문 참여정보는 상세에 남긴다.

공연·편곡은 별도 영상 유형으로 원곡을 덮어쓰지 않는다. 공개 페이지에 날짜만 있으면 `publishedAt: YYYY-MM-DD`, `datePrecision: day`로 기록하고 시각·시간대를 추정하지 않는다. canonical URL 또는 현재 영상 메타데이터의 영상 ID, 본문 제목과 업로더 ID가 모두 일치해야 공개 날짜를 채택한다. 기존 음반 발매일은 그대로다.

RE : WIND의 공식 MV `fgSXAKsq-Vo`는 재등록하지 않는다. 리와인드/REWIND/RE:WIND 검색과 기존 오리지널 곡의 공식 MV·오디오 필터를 지원한다. 일배치 보고서에 `waktaverseIds`, `waktaverseHistory` 검증 결과를 남긴다.


### 활동기록 주간 갱신 (정기 수집 총 4개)

`history-monthly.yml`(기존 파일명 유지): 매주 일요일 00:00 한국시간, cron `0 15 * * 6` (UTC 토요일 15:00). GitHub 러너 대기에 따라 실제 시작은 늦어질 수 있다. 수동 실행·지연 실행도 최근 완료된 일요일~토요일 주간의 마지막 날짜를 마감일로 사용한다. 매일 또는 매배포 실행은 하지 않는다. `ISEGYE_HISTORY_CADENCE=weekly`를 수집과 게시에 동일하게 적용한다. 기존 월간 스냅샷과 ID·저장 경로는 유지하고 새 스냅샷의 `cadence: weekly`로 주간 마감을 검증한다.

기존 `visuals/history.json`의 검토된 55개 기록은 그대로 보존한다. 최초 보충 범위는 기존 검토일이 속한 2026년 10월 1일부터 직전 토요일까지이며, 이후 성공한 자료를 누적하여 중복 없이 보충한다. 공식 뉴스룸·베리즈 공개 공지·이미 원문/작성자가 검토된 카페 공지 중 발매·공연·협업·오디션·수상·주요 콘텐츠 관련 소식, 기존 9개 공식 음악 출처의 커버 이외 음악 공개 기록을 사용한다. 위키나 비공개 페이지를 새로 자동 수집하지 않는다.

새로 조회한 공개 자료와 운영의 누적 일정/음악 스냅샷을 병합하되 다른 피드에는 쓰지 않는다. 짧은 최신 목록에만 의존해 이미 수집된 이전 기록을 놓치지 않게 한다. 공개 목록의 조회 범위 밖이거나 일배치 자체에 수집되지 않은 자료까지 완전하게 망라한다고 보증하지 않는다. 캘린더의 예정일이 지났다는 이유만으로 개최/발매 완료로 바꾸지 않는다. 영상 공개는 콘텐츠 기록, 공식 공지는 소식 게시일 기록으로 표시하며 실제 행사일·음반 발매일과 구분한다. 향후 일정 자체, 팬 추측, 일반 방송/휴방·배송 안내, 미확인 게시글은 자동 연혁에 넣지 않는다.

누적 결과는 전용 `.history-feed/current.json`과 직전 백업에만 원자적으로 기록하고 서버 재조회로 검증한다. `/api/history`는 기존 로그인/점검 정책 뒤에서 제공한다. 실패하면 검토된 자료 및 이전 성공 결과를 유지하고, 각 출처의 원래 확인시각을 보존한다. 전부 실패하면 갱신하지 않는다. 일부 실패는 보고서와 주간 갱신 안내에 명시한다.

결과는 `weekly-history-*` 아티팩트의 `history-discovery.json`、`history-publication.json`에 90일 보관한다. 추가/수정/누계, 주간 마감일, 실제 원문과 확인일, 출처별 상태, 저장 후 재검증 여부를 남긴다. `ISEGYE_HISTORY_PAUSED=true` 또는 공통 `PRODUCTION_PAUSED=true`로 중지한다.
